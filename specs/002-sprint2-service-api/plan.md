# Implementation Plan: Sprint 2 — Service Layer & REST API

**Branch**: `002-sprint2-service-api` | **Date**: 2026-05-05 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/002-sprint2-service-api/spec.md`

---

## Summary

Wire the existing Sprint 1 domain model and Redis repositories behind a thin service layer
(`RateLimiterService`) and expose a fully-tested HTTP API via Ktor: `POST /v1/check`,
CRUD on `/v1/limits`, and `GET /health`. All integration tests run against a real Redis
instance via Testcontainers. The only interface change from Sprint 1 is
`ConfigRepository.delete` returning `Boolean` instead of `Unit` to support the 404 response
on DELETE without an extra round trip.

## Implementation Notes

### `ConfigRepository` interface change

`suspend fun delete(key: String): Boolean`

Required to support DELETE 404 without a `get()+delete()` round trip. Both existing
implementations updated; `InMemoryConfigRepository` uses `ConcurrentHashMap.remove()` return
value; `RedisConfigRepository` uses `DEL` command's returned count.

### `RateLimitKey` value class

```kotlin
@JvmInline
value class RateLimitKey(val value: String) {
    init { require(value.isNotBlank()) { "key must not be blank" } }
}
```

Route layer validates blank before constructing; the `init` block is a defense-in-depth guard.

### `InstantSerializer`

10-line custom `KSerializer<java.time.Instant>` (ISO-8601 string). Applied on
`CheckResponse.resetAt` via `@Serializable(with = InstantSerializer::class)`. No new
dependencies required.

### Application wiring (`Application.kt`)

```
loadConfig (Hoplite) or use overrideConfig parameter
  → RedisClient.create(RedisURI)
  → connection = client.connect()
  → commands = connection.coroutines()
  → RedisRateLimitRepository(commands)
  → RedisConfigRepository(commands)
  → RateLimiterService(rateLimitRepo, configRepo, appConfig)
  → install(ContentNegotiation) { json() }
  → install(StatusPages) { UnsupportedMediaTypeException→415, BadRequestException→400,
      JsonConvertException→400, Throwable→500 (all ErrorResponse) }
  → routing {
      route("/v1") {
        checkRoute(rateLimiterService)
        limitsRoute(configRepo)
      }
      healthRoute(commands)
    }
  → environment.monitor.subscribe(ApplicationStopped) {
      connection.close()
      redisClient.shutdown()
    }
```

The `overrideConfig: AppConfig? = null` parameter enables test injection without modifying
the Hoplite loading path.

### Health check timeout

```kotlin
try {
    withTimeout(1_000L) { commands.ping() }
    "UP"
} catch (_: TimeoutCancellationException) { "DOWN" }
catch (_: Exception) { "DOWN" }
```

Catches `TimeoutCancellationException` before generic `Exception` to avoid swallowing parent
scope cancellations.

### Testcontainers singleton

```kotlin
object RedisTestContainer {
    val container: GenericContainer<*> =
        GenericContainer(DockerImageName.parse("redis:7-alpine"))
            .withExposedPorts(6379)
            .also { it.start() }

    val host: String get() = container.host
    val port: Int get() = container.getMappedPort(6379)
}
```

All integration test classes reference `RedisTestContainer.host` / `.port`. FLUSHDB called
in `@BeforeEach` of each test class.

### Integration test structure

Each IT class:
1. `@BeforeEach`: connect to `RedisTestContainer`, `FLUSHDB`, close connection
2. Wraps each test in `testApplication { application { module(testConfig) } }`
3. Uses Ktor `client` to make HTTP calls and assert status + body

`testConfig` = `AppConfig(server = ServerConfig(0), redis = RedisConfig(host, port), rateLimit = RateLimitDefaults())`

## Test Cases Checklist

### `CheckRouteIT`
- `returns allowed=true when under limit`
- `returns allowed=false when limit exceeded`
- `returns 400 when key is blank`
- `uses default policy when no policy configured`

### `LimitsRouteIT`
- `POST creates policy and returns 201`
- `POST returns 400 for blank key`
- `POST returns 400 for negative limit`
- `POST returns 400 for zero windowSeconds`
- `POST returns 400 for unknown strategy`
- `GET returns policy when exists`
- `GET returns 404 when not found`
- `DELETE returns 204 and policy is gone`
- `DELETE returns 404 when not found`

### `HealthRouteIT`
- `returns 200 UP when Redis available`
- `returns 503 DOWN when Redis unavailable` (container paused via Testcontainers `pause()`)
